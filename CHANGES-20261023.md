# Folder Locker repair set — 2026-10-23

## Android app
- The app opens `animations.html` without forcing the `#login` route, so the animation sequence begins at screen 1 on launch and continues through screen 3 before login for existing users.
- Existing users bypass only the first-time password registration and vault-securing progress screens. New users still see registration and progress on the first run.
- Android WebView uses `adjustResize` for the on-screen keyboard.
- Images, Videos, Music, Documents and Category menus support the same multi-select move-back-to-phone-storage flow as Files. The source-vault copy is removed only when the native export reports a verified copy.

## Install page and community
- The community uses site-wide Netlify Blobs key-value stores for accounts, username indexes, hashed-password records, sessions, posts, likes, comments, replies, announcements and profile-picture bytes. Supabase functions, service-key usage, SQL migration files, and the old bundled Supabase ZIP have been removed.
- The Register/Login selection is preserved if the initial online request succeeds or fails while the visitor is typing, preventing the page from switching away from the registration form and dismissing the keyboard.
- Registration inputs disable automatic capitalization and autocorrect. Profile pictures support JPG, PNG, WEBP and GIF up to 3 MB to stay below the function request limit after Base64 encoding.
- The install page no longer asks users to confirm that they installed the app. Its counter increases after the full APK body has been fetched and received by the page. If cross-origin download access is blocked, the official direct-download fallback proceeds without falsely incrementing the counter.
- This counter measures receipt of the complete APK response by the page, not that Android saved the file or finished installation.

## Current limitations / rollout
- Netlify Blobs is simple persistent key-value storage, not a relational SQL database or transactional data store. It is suitable for this starter community; a growing high-traffic community may need a managed relational database later.
- Existing Supabase-hosted accounts/posts are not automatically migrated to the new store. Once this source is deployed, visitors may need to create accounts again.
- JavaScript syntax, XML parsing, mocked store-backed community interactions, counter routes, and ZIP integrity are checked locally. Live Netlify deployment, live Blobs credentials/runtime, GitHub Actions APK build, and physical-phone feature testing have not been performed from this workspace.

## Sample audio correction
- The bundled sample audio is now exactly `sound1.mp3`, `sound2.mp3`, and `sound3.mp3`. `sound1.mp3` is unchanged; `sound2.mp3` contains the exact original `sound4.mp3` audio; `sound3.mp3` contains the exact original `sound5.mp3` audio. The old `sound2.mp3`, `sound3.mp3`, and `sound6.mp3` sample payloads are not bundled.
- On upgrade, Android checks SHA-256 against the known old sample payloads, removes only matching old sample copies (`sound2.mp3`, old `sound3.mp3`, and `sound6.mp3`), and renames matching old `sound4.mp3`/`sound5.mp3` vault samples to `sound2.mp3`/`sound3.mp3`. User audio with different content is left untouched.
